# Installation

Kubera is a single binary with its detectors built in. Pick the install that suits you, then check it with `kubera --version`. Next: [Your first scan](quickstart.md).

## One-line install (Linux, macOS, Termux)

```bash
curl -fsSL https://raw.githubusercontent.com/dmdhrumilmistry/kubera/main/install.sh | sh
```

The script picks the prebuilt binary for your OS and CPU (static Linux musl, macOS Intel/Apple Silicon, Android/Termux aarch64), **verifies its SHA-256 checksum** and installs it to `~/.local/bin` (or `$PREFIX/bin` on Termux). Set `KUBERA_VERSION=v0.1.0` to pin a release or `KUBERA_INSTALL_DIR` to change the location. Read the script first if you prefer: it's short.

## One-line install (Windows)

In PowerShell (Windows PowerShell 5.1 or PowerShell 7):

```powershell
irm https://raw.githubusercontent.com/dmdhrumilmistry/kubera/main/install.ps1 | iex
```

The script picks the x86_64 or ARM64 zip for your CPU, **verifies its SHA-256 checksum**, installs `kubera.exe` to `%LOCALAPPDATA%\Programs\kubera\bin` and adds that folder to your **user** PATH (no administrator rights needed; open a new terminal afterwards). It understands the same variables as `install.sh`:

| Variable | Effect |
|---|---|
| `KUBERA_VERSION` | Release tag to install, e.g. `v0.2.0` (default: latest) |
| `KUBERA_INSTALL_DIR` | Install folder |
| `KUBERA_NO_MODIFY_PATH` | `1` leaves your PATH alone |

```powershell
$env:KUBERA_VERSION = 'v0.2.0'; irm https://raw.githubusercontent.com/dmdhrumilmistry/kubera/main/install.ps1 | iex
```

Re-running the script upgrades in place, even while an old `kubera.exe` is running. To read it before running it, download it first: `irm https://raw.githubusercontent.com/dmdhrumilmistry/kubera/main/install.ps1 -OutFile install.ps1`.

## Package managers

Every manifest below installs the same release archives as the installers, pinned by their SHA-256, and is generated by the release workflow from the published checksums. Upgrade with the package manager's own command.

| Package manager | Platforms | Install | Upgrade |
|---|---|---|---|
| [Homebrew](https://brew.sh) | macOS (Intel, Apple silicon), Linux (x86_64, aarch64) | `brew install dmdhrumilmistry/tap/kubera` | `brew upgrade kubera` |
| [Scoop](https://scoop.sh) | Windows (x86_64, ARM64) | `scoop bucket add kubera https://github.com/dmdhrumilmistry/scoop-bucket` then `scoop install kubera/kubera` | `scoop update kubera` |
| [winget](https://learn.microsoft.com/windows/package-manager/) | Windows (x86_64, ARM64) | `winget install dmdhrumilmistry.kubera` | `winget upgrade dmdhrumilmistry.kubera` |
| [AUR](https://aur.archlinux.org/packages/kubera-bin) | Arch Linux (x86_64, aarch64, armv7h) | `paru -S kubera-bin` (or `yay -S kubera-bin`) | `paru -Syu kubera-bin` |

Each release also carries `kubera-packaging-vX.Y.Z.tar.gz` with the rendered Homebrew formula, Scoop manifest, winget manifests and AUR `PKGBUILD`/`.SRCINFO`, if you keep your own tap, bucket or repository. The templates live in [`packaging/templates/`](https://github.com/dmdhrumilmistry/kubera/tree/main/packaging/templates), and [`packaging/`](https://github.com/dmdhrumilmistry/kubera/tree/main/packaging) has them rendered for the current release.

The winget manifests use the zip's `kubera.exe` as a portable command, so `kubera` is on your PATH after installing. The binary is linked against the Visual C++ runtime (`vcruntime140.dll`), which nearly every Windows install already has; if `kubera` fails to start with a missing DLL, install the [Visual C++ Redistributable](https://learn.microsoft.com/cpp/windows/latest-supported-vc-redist).

## Cargo

```bash
cargo install kubera-cli --locked
```

The crate is called `kubera-cli` (the `kubera` name on crates.io belongs to an unrelated project); the installed command is `kubera`. Requires Rust **1.88** or newer ([rustup](https://rustup.rs)).

## Prebuilt binaries

Every [GitHub release](https://github.com/dmdhrumilmistry/kubera/releases) has archives for Linux (x86_64, aarch64, i686, armv7, armv6 static musl; riscv64 glibc), Android/Termux (aarch64, armv7, x86_64), macOS (x86_64, arm64), Windows (x86_64, ARM64) and FreeBSD (x86_64), each with a `.sha256` file, a Sigstore signature bundle (`.sigstore.json`) and a GitHub build provenance attestation. The release also carries a CycloneDX SBOM, `kubera-vX.Y.Z.cdx.json`.

## Verifying a release

The installers always check the SHA-256. Releases published after v0.2.0 are also signed and attested by the release workflow itself, with short-lived [Sigstore](https://www.sigstore.dev) certificates bound to GitHub's OIDC identity for `dmdhrumilmistry/kubera/.github/workflows/release.yml`: no long-lived signing key exists that could leak. To check that an archive was built by that workflow from this repository:

```bash
# GitHub CLI: build provenance (which commit, which workflow run).
gh attestation verify kubera-x86_64-unknown-linux-musl.tar.gz --repo dmdhrumilmistry/kubera

# The SBOM attestation for the same archive.
gh attestation verify kubera-x86_64-unknown-linux-musl.tar.gz --repo dmdhrumilmistry/kubera \
  --predicate-type https://cyclonedx.org/bom

# cosign: the detached signature bundle next to the archive on the release.
cosign verify-blob kubera-x86_64-unknown-linux-musl.tar.gz \
  --bundle kubera-x86_64-unknown-linux-musl.tar.gz.sigstore.json \
  --certificate-identity-regexp '^https://github\.com/dmdhrumilmistry/kubera/\.github/workflows/release\.yml@refs/(heads/main|tags/v[0-9.]+)$' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

The same works for `kubera-vX.Y.Z.cdx.json` and `kubera-packaging-vX.Y.Z.tar.gz`. To make the installer check the attestation too (on top of the checksum, never instead of it), install the [GitHub CLI](https://cli.github.com), run `gh auth login`, and set `KUBERA_VERIFY_ATTESTATION=1`:

```bash
curl -fsSL https://raw.githubusercontent.com/dmdhrumilmistry/kubera/main/install.sh | KUBERA_VERIFY_ATTESTATION=1 sh
```

```powershell
$env:KUBERA_VERIFY_ATTESTATION = '1'; irm https://raw.githubusercontent.com/dmdhrumilmistry/kubera/main/install.ps1 | iex
```

Container images are signed by digest and carry a provenance attestation in the registry:

```bash
cosign verify ghcr.io/dmdhrumilmistry/kubera:latest \
  --certificate-identity-regexp '^https://github\.com/dmdhrumilmistry/kubera/\.github/workflows/release\.yml@refs/(heads/main|tags/v[0-9.]+)$' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
gh attestation verify oci://ghcr.io/dmdhrumilmistry/kubera:latest --repo dmdhrumilmistry/kubera
```

## Container image

Every release publishes a multi-architecture image (linux/amd64, linux/arm64) to GitHub Container Registry, built from the same static binaries as the release archives:

```bash
docker run --rm ghcr.io/dmdhrumilmistry/kubera --version
docker run --rm -v "$PWD:/scan" ghcr.io/dmdhrumilmistry/kubera scan git /scan
docker run --rm -v "$PWD:/scan" ghcr.io/dmdhrumilmistry/kubera scan fs /scan --fail
docker run --rm ghcr.io/dmdhrumilmistry/kubera scan image alpine:3.20
```

| Tag | Meaning |
|---|---|
| `0.2.0` | One release |
| `0.2` | Latest patch release of 0.2 |
| `latest` | Latest release |

- The entrypoint is `kubera`, and the working directory is `/scan`: mount what you want scanned there.
- The image runs as a **non-root** user (uid 10001) and includes `git` and CA certificates. Mounted repositories owned by another uid are accepted by git.
- Pass credentials as environment variables, for example `-e GH_TOKEN` with `--token-env GH_TOKEN`.

To build it yourself from a checkout:

```bash
docker build -t kubera .
docker run --rm -v "$PWD:/scan" kubera scan git /scan
```

## From source

```bash
git clone https://github.com/dmdhrumilmistry/kubera
cd kubera
make install            # or: cargo build --release
kubera --help
```

The builtin templates are embedded in the binary, so you can copy `kubera` anywhere on its own.

## Termux (Android)

Kubera builds and runs natively in [Termux](https://termux.dev):

```bash
pkg install rust git make clang
git clone https://github.com/dmdhrumilmistry/kubera
cd kubera
make install          # installs to $PREFIX/bin, already on your PATH
kubera templates test
```

Everything works, including `--verify`, `analyze` and `rotate`. Android's built-in certificate verifier can only be used from Java, so on Android Kubera verifies TLS against an explicit set of trusted roots, taken from the first of these that exists:

1. `SSL_CERT_FILE`, if set (a PEM bundle);
2. Termux's CA bundle, `$PREFIX/etc/tls/cert.pem` (from the `ca-certificates` package, installed by default);
3. Android's system store (`/apex/com.android.conscrypt/cacerts` on Android 14+, `/system/etc/security/cacerts` before that);
4. Mozilla's root list, compiled into the binary.

If you use a TLS-intercepting proxy (common on corporate networks), add its CA to Termux's bundle or point `SSL_CERT_FILE` at a bundle that contains it.

CI builds and tests every change inside a Termux container (`make test-termux`).

## Makefile

The repository ships a `Makefile` for common tasks. Run `make help` for the list:

| Target | What it does |
|---|---|
| `make build` / `make release` | Debug / optimised build |
| `make install` / `make uninstall` | Install to `$(PREFIX)/bin` (default `/usr/local`; Termux sets `PREFIX` for you). Supports `DESTDIR`. |
| `make test` | Unit and integration tests |
| `make lint` | `rustfmt` check and `clippy` with warnings as errors |
| `make templates-test` | Run every template's samples |
| `make scan` | Scan the repository's files and history with Kubera itself |
| `make check` | `lint` + `test` + `templates-test` + `scan` |
| `make docs` / `make docs-serve` | Build or live-serve this documentation (needs `mdbook`) |
| `make tui` | Build and launch the interactive TUI |
| `make screenshots` | Regenerate the documentation images from the real TUI/CLI code |
| `make test-termux` | Build and test inside a Termux container (needs Docker) |
| `make audit` | `cargo audit` (needs `cargo-audit`) |

Examples:

```bash
make install PREFIX=$HOME/.local        # no sudo
sudo make install                       # /usr/local/bin
make install DESTDIR=/tmp/pkg PREFIX=/usr   # staged install for packaging
```

## Runtime requirements

- `git` on `PATH` for `kubera scan git`, `scan repos`, `scan staged` and the pre-commit hook.
- Outbound HTTPS to vendor APIs, only when you use `--verify`, `verify`, `analyze` or `rotate`.

kubera --version
